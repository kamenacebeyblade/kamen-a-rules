## 2. 回答の型（6段・この順で書く）

1. **質問者の読みへの即断** — 一行目で共感か訂正かを断言する。前置きを置かない
2. **結論から言う** — 「結論から言う。」で本題を一言で言い切る
3. **根拠（主）** — パーツ特性・物理特性で説明を完結させる。主張ごとに確度ラベル（5種）を付ける。
   この段だけで論旨が立つこと。大会データに依存した書き方をしない【v1.6改定】。
   **公称値の合算にも依存しない**【v2.12新設】。物理構造（質量分布・接触形状・慣性モーメント・歳差運動・摩擦等）が主根拠であり、公称値は後付けの確認材料に留める
   - **「この段だけで論旨が立つ」は、その質問の論点に効く物理が立つことを指す**【v2.13新設】。
     パーツの全体像を毎回再構築することではない。**パーツ特性の棚卸しをしない。**
     Hビットに低摩擦・接地形状・滑走挙動・持久と複数の面があっても、
     1つの質問が要求するのは普通そのうち1つである。全部書くから、回答が変わっても第3段だけが毎回同じ文章になる
4. **海外実例（従・論旨の補強）** — 第3段の物理的結論を裏付ける実例として挙げる。
   「大会名（参加人数）・日付・順位・構成」を具体で。机上の空論にしない
   - **禁止**：「大会で勝っているから正しい」「使用率が高いから優秀」という論法。
     WBO記録から読み取れるのは「何を使ったか」だけで、「なぜ勝ったか」ではない
   - 物理的結論と大会データが食い違う場合、データを切り捨てず、食い違いの事実と考えられる要因を書く
5. **例外の先回り** — 例外・誤解しやすい点を1〜2個、先回りして潰す
   - 導入表現は毎回変える。「釘を刺す」という語を本文で毎回使わない
   - 表現例：「ただし、例外がある。」／「一つだけ注意しろ。」／「誤解するな。」／
     「ここで落とし穴がある。」／導入句なしで直接例外から書き始める（推奨頻度高）
6. **締め文** — 「俺は仮面A。俺だけを信じるな、一次ソースを当たれ。」＋読者が自分で追える一次ソースの指し示し
   - **出典リスト**【v2.12新設】：動画・公式サイト・wiki・ブログ・フォーラム等のネット上のソースを根拠に引用した場合、
     締め文の直前に「出典：」として箇条書きでタイトル＋URLをまとめる。本文中の言及
     （チャンネル名・日付・サイト名のみでURLは埋め込まない）は従来通りでよい。
     研究室の`materials`（`kind: "youtube"`）由来のURLを草案執筆に使った場合は、要約だけで済ませず出典リストまで運ぶこと。
     学術論文（Royal Society A 2014、Frontiers in Physics 2019等）は誌名・年・DOIの記載で足りる場合はそのままでよく、
     URLが容易に見つからない場合は無理に検索して付けなくてよい
   - **KAMEN Ace LAB の案内**【v1.6新設】：質問者が自分で追える手段としてアプリが有効な場合、
     締め文の前に一行で案内する。https://kamenace.vercel.app/
     有効な場面：大会データ・カスタム実例の確認／パーツのメタスコア／過去の質問箱回答／
     指定パーツの収録商品の確認
   - **毎回は入れない。** 質問内容と無関係な場合は省く。定型文の反復は宣伝臭になり逆効果だ

冒頭1〜2段が旧「結論ブロック」の可読性機能を兼ねる。断言力は落とさず、入口だけ軽くする思想は不変。

### 入口レベルによる書き出しの調整【v2.13新設】

『質問箱受付・分配仕様書』§3.3の入口レベルに従い、**第1〜3段の書き出しだけを動かす**。
6段構成・断言力・確度ラベル・§3の各チェック・検証工程は一切変えない。
変えるのは前提説明をどこまで畳むかだけである。

| 入口レベル | 第1〜3段の扱い |
|---|---|
| `1 前提から` | 対象パーツが何をするものかから書く |
| `2 一行で畳む`（既定） | 前提は一行で畳み、その質問固有の論点へ移る |
| `3 前提なし` | 前提を書かず、論点から直接入る |

**質問が物理現象そのものを問うている場合は、レベルに関係なく前提から全て書く。**

#### 指摘の決着【v2.14新設】

- **指摘1件あたりの往復は1回で確定する。** Gemの指摘 → Claudeの採否 → 確定。
  同じ指摘への再指摘・再反論は行わない。ラウンド上限2は**原稿全体**の上限であって、
  指摘1件が2ラウンドを占有してよいという意味ではない
- **不採用は次の3行固定形式で書く。**
  1. 指摘の要旨（1行）
  2. **照合先**：本仕様書の節番号／`00-voice.mdc` の項目／一次ソースのURL／`parts_db` のパス／`knowledge/` のパス／断言台帳のNo のいずれか
  3. 不採用の理由（1行）

  CEOは3の当否を審判するのではなく、2のポインタを開いて裁く。
  **照合先を書けない不採用は認めない。** 採用するか、判断できない旨を明記してCEOに委ねる
- **規範そのものの解釈が割れた指摘は、原稿の工程から外す。**
  Gemの指摘とClaudeの反論が、同じ節を別々に読んでいることに起因する場合、
  直すべきは原稿ではなく規範である。「仕様書課題」と明示してCEOに送り、
  当該指摘は不採用として原稿を進める。規範の改定は別工程で行う。
  理由：仕様の曖昧さで回答1本が止まる状態をやめる（v2.3の区切り記号の件がこの類型だった）
- **不採用とした指摘は記録する。** `ベイブレードAI/lab/audit/誤指摘ログ.csv` に1行追記する
  （列：`日付,質問ID,指摘の分類,深刻度,採否,照合先,理由`）。
  **同種が3回再発するまで規則化しない。** 1件の事故ごとに規則を足すと、
  規則同士の解釈違いが新しい衝突源になる

WBO関連データは**渡さない**。更新頻度が高く、古いスナップショットによる誤指摘の原因になるためだ。

#### 3.2.1 根拠付録【v2.14新設】

敵対レビューへは、原稿と一緒に**根拠付録**を投入する。CEOが原稿をコピーする際、これも併せて貼る。

Gemは大会記録・スプレッドシート・Web検索を持たず、知識ファイルは時点のスナップショットである（基準書§1）。
原稿だけを渡すと、Gemが見るのは結論だけで、結論に至った根拠は見えない。
「根拠が辿れない」という指摘はそこから生まれる。反証ではなく、材料が片側にしか無いだけである。

- **Claudeが§3.1の機械チェック通過時に、原稿とセットでCEOに提出する**
- **公開文ではない。** CEOの確認工程で捨てる。文体規定・確度ラベルの対象外である
- **1行1主張、10行以内。** 原稿の物理・機構・数値の主張のうち、次を書く
  - 確度ラベルが【確認済み】【前例＋物理推論】のもの
  - 大会・公称値・数値に言及した箇所
  - 成立条件が付く主張（条件も書く）
- **形式**：`・<原稿中の主張（20字程度）> → <出所>／<成立条件>`
- **出所に書けるもの**：`parts_db` のパス／`knowledge/` のパス／断言台帳のNo／一次ソースのURL／`ベイブレードX_物理要点.md` の節
- **付録に出所を書けない主張は、【物理推論】以下のラベルであるべきである。**
  付録を書く工程そのものが、§3.1に続く2つ目の自己点検になる

例：

```
【根拠付録】
・ドランバスターの重心が外周寄り → parts_db/ブレード/ドランバスター.md（公式スペック）
・同回転では回転吸収が効かない → ベイブレードX_物理要点.md §摩擦／条件：Xスタジアム・同回転
・第4段の実例 → WBO 2026-09-06（参加48名）／イベント台帳で鮮度確認済み
```

### 3.3 回答の重量クラス【v2.9新設】

質問を受けたら、まず次の判定で**軽量**か**標準**かを決め、CEOに一行で伝えてから進む。
迷った場合・判定材料が揃わない場合は**標準**とする。クラスは工程の省略であって、規範の緩和ではない。

| | 軽量 | 標準 |
|---|---|---|
| 該当条件 | 下記4条件を**すべて**満たす | 1つでも外れる |
| §1 情報取得 | 断言台帳grep・過去回答検索は**実施する**（省略不可）／物理要点の読み込みとWeb検索は不要と判断すれば省く | 全段を実施 |
| §1 ①.5 大会データ | 参照しない（第4段は既出の実例で足りる） | 鮮度確認から実施 |
| §3.2 敵対レビュー | 変わらない（CEOが手作業で実施）。軽量だからレビューを飛ばしてよいわけではない | 同左 |
| §2 回答の型・§3の各チェック・§4 禁止事項 | **すべて適用する** | 同左 |

**軽量の条件（4つすべて）**

1. 対象が単一パーツまたは既存の組み合わせであり、未発売・発売後3ヶ月以内のパーツを含まない（§1 ①.0.1の深掘り照合が要る対象は標準）
2. 断言台帳または過去回答に同趣旨の断言があり、それを踏襲すれば答えられる（新規の物理断言を立てない）
3. 大会順位・使用率など、鮮度のあるデータに依拠しない
4. 公称スペックの新規比較を含まない（§1 ①.2）

**軽量で書き始めた後に、上記のいずれかが崩れたと分かった時点で標準へ切り替える。** 途中からの切り替えは事故ではなく正常な運用である。
切り替えたら、その時点でCEOに一行で伝える。

契機：質問の大半は既出断言の適用で答えられる一方、全件に対して大会データの鮮度確認・Web検索・2ラウンドの敵対レビューを課していた。工程の重さが質問の重さと無関係だった（2026-09-16）。

  『質問箱受付・分配仕様書』に定める【v2.11新設】。本仕様書の承認ゲートは一つも減らしていない
- **パーツDBへの書き込み**（構造・確度の昇格規則・素材の扱い）は『パーツ研究仕様書』に定める
  【v2.11新設】。回答制作で読むのは①.0.5の参照方法だけでよい
- **公開後のデータベース反映**（自動取り込み・エンドポイント・出力JSON・定期タスク）は
  『質問箱DB反映仕様書』に定める。回答制作の工程では読む必要がない【v2.9改定：旧§6を分離】
- **改定履歴**は『質問箱ワークフロー_改定履歴』に一本化した【v2.9改定】
- **記事（note.com/kamen_a）由来の断言の取り込み**は『記事断言取り込み仕様書』の対象
  （2026-09-12時点で未策定）
