note質問箱の**公開後**の工程——回答を断言台帳へ反映する自動取り込みと定期タスク——は本仕様に従う。
回答の制作工程（情報取得・回答の型・チェック・承認）は『質問箱ワークフロー仕様書』に定める。
本文中の「§6.x」は本仕様書内の該当節を指す。「§1」「§2」「§3」等は『質問箱ワークフロー仕様書』の該当節を指す。

## 6. データベースへの反映【v2.0全面改定】

2026-09-12にWeb App化した。メニュー操作によるテキストの書き出し・貼り付けは廃止。
**CEOの操作は④の承認のみである。**

### 6.1 全体の流れ

```
① note質問箱に回答を公開
        ↓  翌朝4時台・全自動（Google Apps Script）
② 「質問箱」タブに行が追加される
     No／質問URL／質問文／回答全文／公開日／処理状態=未処理
     カテゴリ（E列）とパーツ列（F〜K列）は空のまま
        ↓  毎日9時に定期タスクが通知
③ Claudeが ?type=qabox_pending で未処理分を自律取得する
   （前回確認からの経過日数に関わらず、未処理分を全件まとめて取得する）
        ↓
③.5 各バッチの開始時に、規範文書の版を再確認する【v2.8新設】
   `kamen-a-rules\specs\質問箱DB反映仕様書.md`（本仕様書）の本文1行目を読み、
   前バッチから版が変わっていれば改定内容を確認してから分類に入る【v2.10改定：分割に伴い参照先を本仕様書へ変更】。
   契機：2026-09-15、バッチ処理中に仕様書がv2.6からv2.7へ改定されたが、
   Claude側は初回読み込みの版のまま作業を継続した（実害はなかった）
        ↓
④ カテゴリ・パーツ・断言をJSONで提案（既出照合込み／ハッシュ先頭12桁を併記）
        ↓  CEOが内容を承認
⑤ Claudeが POST ?type=apply で送信。反映結果はレスポンスで即返る
     E〜K列が埋まり、断言台帳タブに行が追加され、処理状態が「済」になる
     Drive上の assertions_latest.csv も自動で更新される
```

- **③はCEOの明示指示を待たない。** 毎日9時の定期タスクが発火した時点で、Claudeは取得と分類まで進める
- ただしClaudeに独立した起動トリガーはない。動作するのは定期タスクでセッションが立ち上がった時のみである。CEOがその日に開かなければ処理は行われず、未処理分は翌日以降にまとめて提示される（取りこぼしにはならない。§6.6参照）
- **④の承認ゲートは廃止しない。** 無承認で断言台帳に書き込むことはしない
- 分割して進めてよい。10件程度を1バッチとする。断言は1件あたり2〜6本のため、10件で40本前後になり、CEOが目を通せる分量に収まる

### 6.2 エンドポイント

接続情報は `kamen-a-workflow/.env`【v2.6改定】。キー構成は同リポジトリの `.env.example` を参照する（`WEB_APP_URL` / `API_TOKEN` / `SHEET_ID` / `QABOX_GID` / `RULES_DIR` / `DATA_DIR` ほか）。`.env` は `.gitignore` で保護されており、派生形（`.env.txt` 等）も除外対象である。実装の詳細は『仮面A パイプライン自動化 実装仕様書』に置く。

**接続情報を他のファイルへ複製しない**。旧 `pipeline_config.md` は同一の値を平文で保持し、かつgit管理外のフォルダに置かれていたため廃止した。

**`API_TOKEN` をローカル環境の外へ持ち出さない**【v2.8新設】。`.env` を読んで値を別の実行環境（クラウド上のシェル等）へ渡す運用は、経路や相手を問わず禁止する。ローカルシェルが使用不能な場合は**作業を中止し、CEOに報告する**。代替経路での続行は認めない。契機：2026-09-15、device_bashが不具合で使用不能だったため、`.env` の値を読み取ってクラウド環境からcurlを実行した事例が発生した。WEB_APP_URLが公開エンドポイントであることと、トークンが手元を離れることは別の問題である。

| 種別 | 用途 |
|---|---|
| `GET ?type=qabox_pending` | 未処理分の取得。`limit` `offset` で分割できる |
| `GET ?type=ledger` | 断言台帳CSV（§1 ①.0.2） |
| `GET ?type=health` | 診断。未処理件数・台帳行数・イベント台帳の鮮度 |
| `POST ?type=apply` | 分類JSONの反映。トークン必須 |

**curlでPOSTする際に `-X POST` を付けてはならない。** Apps Scriptは302で結果URLへ誘導するため、
メソッドを固定すると405になる。`--data-binary` のみで送ること。

```bash
curl -sL -H "Content-Type: application/json" \
     --data-binary @post.json "$WEB_APP_URL?token=$API_TOKEN"
```

`qabox_pending` は、シートに `\n` リテラルで格納された回答本文を**実改行に復元して返す**。
復元されていない場合はエンドポイントの不具合であり、そのまま分類してはならない。

### 6.3 自動取り込みの仕様（Apps Script）

- 対象：`https://note.com/qa/kamen_a` の公開ページ。生HTMLに最新20件の
  個別URL・質問全文・回答全文・公開日時（ISO8601）がserver-rendered DOMとして含まれる
- 実行：毎日4時台。1日1リクエスト
- 重複判定：質問URL（32桁ハッシュ）。既存行と一致すればスキップする
- 採番：**公開日の昇順（No.1が最古）**。複数件を同時に取り込む場合も必ず昇順に並べてから
  最大No+1を付与する。HTMLの表示順（新しい順）をそのまま使ってはならない
- D列の改行は `\n` リテラルで格納する（既存385行と同形式）。
  KAMEN Ace LABアプリ側で実改行へ復元して表示している
- **1日の新規回答が20件を超えると溢れた分は取り込めない。** 想定運用では問題ないが、
  大量公開した場合は「いま取り込む」を当日中に手動実行すること
- 健全性チェック：メニュー「パーサーを自己診断」、または `?type=health`。
  noteのリニューアルでHTML構造が変わると抽出0件になる。その場合はパーサーの修正が必要

### 6.4 Claudeが出力するJSON

```json
{
  "type": "apply",
  "payload_hash": "sha256:...（64桁）",
  "payload": {
    "questions": [
      {"no":"386","category":"カテゴリ名","blades":"","ratchets":"","bits":"","lockchips":"","overs":"","assists":""}
    ],
    "assertions": [
      {"no":"386","claim":"断言の全文。","label":"【物理推論】","note":"根拠の出所。"}
    ]
  }
}
```

**出典記事・公開日・備考末尾の質問URLは出力しない。** スクリプトが自動生成する。
これにより、過去に事故った全角コロン（`質問箱：`）の表記ゆれと質問URLの欠落が
構造的に起きなくなった。

**ハッシュによる承認内容の担保**【v2.0新設】

- `payload_hash` は `payload` のみを対象とする。キーを再帰的に昇順ソートし、
  区切り文字なしのminified JSONにしてUTF-8でSHA-256を取る
- **Claudeは分類結果をCEOに提示する際、ハッシュ先頭12桁を必ず併記する**
- GASは受信payloadからハッシュを再計算し、不一致・欠落なら**何も書き込まず**400を返す
- レスポンスに受理したハッシュが含まれる。CEOは提示時の値と目視照合できる
- 承認後にClaudeが内容を変更すればハッシュが変わるため、必ず検出される

**二重送信の防止**：同一ハッシュを24時間以内に再受信した場合、書き込まず `duplicate: true` を返す。
通信エラーからの再送で断言が二重登録されることはない。

検証は従来どおりである。カテゴリが既定9種以外、確度ラベルが規定外、
断言や備考が空、存在しないNo——いずれか1つでも見つかれば**何も書き込まずエラー一覧を返す**。
中途半端な反映は起きない。

### 6.5 各項目の記載ルール

- **カテゴリ**：質問箱CSVリスト生成仕様書§1の**既定9種のみ**から選択。複数は `;` 区切り。
  新カテゴリの追加はCEO承認を要する
- **パーツ列**：parts.csvの表記に厳密に従う（取得は①.0.4）。複数は `;` 区切り。該当なしは空文字
  - `overs`（オーバーブレード）と `assists`（アシストブレード）は略号が重複する（`F` `B` 等）。
    略号だけで判別せず、必ず種別で振り分ける。CX表記のパースは1文字目＝オーバー、2文字目＝アシスト
  - 既知の罠：ローラッシュ（×ロウラッシュ）／シャークスケイル（×シャークエッジ）／
    ワイバーンホバー（×ワイバーンゲイル）／ティラノビート（×タイラノビート）
- **断言**：回答本文から、検証可能な主張文のみを抜き出す。締め文・質問者への呼びかけ・修辞は
  対象外。原文の表現を尊重しつつ、単独で意味が通る文に整形してよい。1回答あたり2〜6本が目安
- **確度ラベル**：規定5種、または「【確認済み（出典名）】」形式。**台帳では全ラベルを省略せず明示する**。
  §2の非表示ルールは公開文のみに適用し、転記元は剥離前の原稿とする
- **備考**：根拠の出所を簡潔に。一次ソース名／実測ファイル名／物理式／データ集計範囲のいずれか。
  空欄にしない
- 既出断言と重複する内容は追記しない。既存台帳の方が出典が明確な場合は、そちらを正とする
- 既出断言と矛盾する断言を見つけた場合、**サイレント修正するな。** JSONから除外し、
  CEOに報告して判断を仰ぐ

### 6.6 定期タスク

| タスク | タイミング | 内容 |
|---|---|---|
| 【毎日9時】質問箱 未処理分の分類・断言台帳への反映 | 毎日9時 | §6.1の③〜⑤を手順つきで案内。前日以前の未処理分が残っている場合は、当日分と合算してまとめて提示する |

**CEOがその日に確認できなくても取りこぼしにはならない。** `?type=qabox_pending` は処理状態=未処理の行を
日付を問わず全件返すため、未確認日が続いても翌日以降に合算されるだけである。ただし放置期間が長引くと
1回あたりの提示件数が増える（§6.1末尾の10件/バッチの目安を超える場合は複数回に分けて進める）。

**第1・第3水曜のCSV同期タスクはv2.0で廃止した。** 断言台帳はWeb Appから都度取得するため、
プロジェクトファイルへの差し替え作業は存在しない。

毎回ゼロから手順を説明する。CEOは運用を忘れやすいと自認しているため、
「前回と同じです」で省略しない。

### 6.7 手動退避路

Web Appが停止した場合に備え、メニュー「質問箱 → 反映する」を残してある。
JSONを直接貼り付けて反映できる（ハッシュ検証は経由しない）。
**常用しないこと。** ハッシュによる承認内容の担保が働かないためである。

メニュー「未処理を書き出す」はv2.0で撤去した。`exportPending` 関数の本体は
`readPending_` が `?type=qabox_pending` から参照されているため残してある。

### 6.8 本仕様書の範囲外

記事（note.com/kamen_a）由来の断言の取り込みは、本仕様書の対象外である。
以下は別途『記事断言取り込み仕様書』に定める（2026-09-12時点で未策定）。

- 記事本文の取得と改訂検知（本文ハッシュによる再キューイング）
- WBOレポート由来の断言の選別（順位・スコアのスナップショットは台帳に登録せず、
  集計方法の定義・物理的考察・パーツ特性の恒久的断言のみを対象とする）
- 記事タイトルの命名規則（2026-09-15以降適用）

記事を公開した場合、当面は従来どおり断言台帳の更新プロンプトを手動で回す。
